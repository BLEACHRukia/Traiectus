## 一、改了哪些（严格按任务单，未越界）

| 编号 | 改动 | 落点 | 关键实现 |
|---|---|---|---|
| **P0-1** | 「Windows 端在线」单一真相 | `MiniKVMClient.swift` 新增 `LinkAvailability` | `NSLock` 保护的 Bool；**TCP ready 且 3 秒内有 PONG** 才算在线；500 ms 看门狗判定；断线（`.failed/.cancelled/BYE/接收错误`）立即置 false |
| **P0-2** | 离线时抑制**输出动作** | `KeyboardLink.swift`：`perform()` 与 `handleHint()` 前置 `isOnline` 判断 | 抑制「切屏(m1ddc) + 发 MODE + Warp 光标」三件事；**本地键盘归属照常更新**（两路触发源 kvm-keywatch 事件与 UDP 45790 抢跑都挡） |
| **P0-3** | 离线复位 / 恢复同步 | `KeyboardLink.resetOnOffline()` / `syncAfterRecovery()` | 复位：清过渡态与抢跑提示、**保留本地键盘归属**；恢复：键盘在 Mac → 主动 `MODE Mac`；不在 Mac → 不做动作 |
| **P1** | 自适应重连 + 日志降噪 | `MiniKVMClient.scheduleReconnect()` / `logConnectFailure()` | 离线前 30 秒维持 ≤1 秒退避，之后 **10 秒一次**；失败日志离线 30 秒后改为每 10 次一行 |
| **P2** | UI 三态 | `MiniKVMClient.swift` 的 `ContentView` | 绿=在线（文案「已连接（Windows 端在线）」）/ 橙=连接中 / 灰=Windows 端未运行；离线时追加橙色提示行，并置灰「键盘联动」勾选框（文案改为「Windows 端未运行，联动暂不可用」） |
| **P3** | 断线保险 | `KeyboardLink.resetOnOffline()` 第一句 | 无条件 `CGAssociateMouseAndMouseCursorPosition(1)`，防 warp 后解绑导致指针卡死 |

**未改动（任务单要求）**：`EventInjector` 鼠标注入逻辑一行未动、滚轮手感未动、`m1ddc` 未动、`kvm-keywatch` 未动、
握手协议未动、端口未动（TCP 45789 / UDP 45790 / UDP 45791 全部保持）。

## 四、与 Win 端的接口面

- **协议、端口、握手、心跳、服务端与桥接逻辑：全部未变**（Win 端无需为本改造做任何修改）
- Mac 端新增的判定完全基于**既有**的 `PING/PONG` 与 `MODE`，没有新命令
- 唯一"可感知"的变化：Win 端不在线时，Mac 端**不再执行 Fn 联动**（这正是本改造的目的）

---

## 五、遗留与建议

1. **离线时如果用户仍按 `Fn+Caps`**：键盘会物理去 Windows，屏幕留在 HDMI（Mac）——按任务单 §3.3 的设计，
   需要用户按一下显示器机身按键切到 DP。这是刻意为之（避免"切过去没鼠标"）。
2. **回到 Mac**：键盘 `Fn+T` + 显示器机身按键切回 HDMI（Mac 端此时被抑制，不会自动切屏）。
3. 若将来希望"离线时也能自动切屏"，需要给 Windows 侧一个常驻的最小代理（例如只做显示器 DDC 转发），
   与本次"纯净环境"的目标冲突，建议保持现状。
