# Windows 发送队列改为事件唤醒

## 问题与证据

网线实际移动测试的应用往返约 1 ms，但 Windows 每秒发送峰值中位数为 15.7 ms。
原来的 select 使用 1 ms 超时；入队线程没有通知网络线程。配置超时不能保证实际调度等待。

## 实现

- 用自动复位事件通知队列入队，用 WSAEventSelect 通知 accept/read/write/close。
- 线程只在 socket、队列、退出事件或心跳/关闭期限到来时唤醒，不修改系统计时器精度。
- 阻塞发送保留半行，等待 FD_WRITE；协议错误先发完再关，关闭等待不受过期心跳影响。
- 每批最多1024行，剩余队列再次通知；延迟在 send 接受完整行时计入，包括批次边界。
- 停止先通知并 join 网络线程，再关闭 listener 和事件，避免退出与 socket 句柄使用竞争。
- 私有工作区 Windows 服务端先同步已发布 85b0a4a 的本地化/网卡信息基线，保留已上线功能。

## 验证

Windows CI 调用生产 NetworkThread/EnqueueLine/FlushOutput，测试握手错误刷出、空闲唤醒、
1400行批次、按键/滚轮顺序、换客户端、背压恢复、溢出、心跳超时和空闲退出。
另外同一CI机器对旧轮询版与事件版分别进行200个事件的发送等待测量。
这些测试不注册 Raw Input、不锁光标、不访问真实配对数据，不证明物理鼠标最终显示耗时。

先优化 Windows 并做用户机器相同动作对比，再进行 Mac 网络变化重连优化。
版本仍为0.1.0；发布时只替换 Windows 包里的服务端，保留托盘、配置模板和 Mac 下载包。

## CI 结果与发布纠正

同一原生 Windows CI 的200事件对照：旧轮询 median0.141/P95 15.826/max16.606ms；
事件唤醒 median0.024/P95 0.044/max0.078ms。以上是软件队列等待，不是物理鼠标最终延迟。
现场旧版统计使用每秒峰值，因此不能与CI逐事件分布直接作等同对比。
