# 排查手册

按"从最常见的开始"排序。每一步都写了**看哪里**和**判据**。

---

## 0. 先看日志，别猜

| 端 | 日志 |
|---|---|
| Mac | `~/Library/Logs/Traiectus.log`（启动时的 `[配置]` 那一行会显示实际生效的参数） |
| Windows 服务端 | 服务端窗口，同时落盘到 `windows\phase3-tcp\build\server-live.log` |
| Windows 抢跑读帧 | **在服务端日志里**（3b 起由服务端自己做，不再有独立的桥接进程/日志） |
| 系统电源事件 | Mac 上 `pmset -g log \| grep -E "Entering Sleep\|Wake from"` |

---

## 1. Mac 连不上 Windows

按这个顺序查，**八成是前两条**：

1. **Windows 服务端到底在不在跑** —— Mac 日志会一直显示重连。服务端是手动入口（托盘），
   不是开机自启，这是刻意设计。
2. **防火墙**：Windows 要放行 **TCP 45789**（协议）和 **UDP 45790**（抢跑帧 + 心跳回程；
   控制权切换走的是 TCP，不需要 UDP 45791，但早期规则里留着它也无害）。
   仓库里有 `windows/control-channel/Traiectus-firewall.ps1`。
3. **口令不一致**：Mac 端填的口令要和 `windows/phase3-tcp/token.txt` 一致（同一个词，别带空格）。
   握手失败在 Mac 日志里是 `ERR`，面板显示"异常"。
4. **是不是开了两个客户端**：日志里如果反复出现
   `已多次「握手成功后又失联」` —— 服务端同一时刻只接受一个客户端，先确认没有第二份实例在跑。
5. **网段是否真的通**：先在 Mac 上 `nc -z <Windows-IP> 45789`。

---

## 2. Mac 上鼠标不动（但能看到光标被"锁"在 Windows 中间）

1. **辅助功能权限**：系统设置 → 隐私与安全性 → **辅助功能** → Traiectus 打勾。
   日志里会直接写 `[启动] 辅助功能权限：未授权`。
2. **鼠标必须是"无线"那条链路**：Windows 侧服务端按设备过滤（`--device VID_…`）只读捕获
   2.4G 接收器的输入。鼠标改成有线（直连）时设备 ID 变了，要先在
   `windows/phase3-tcp/` 里重新确认 device id（`list-rawinput-devices.ps1`）。
3. **重编之后权限又掉了**：ad-hoc 签名会让每次重编都换掉 TCC 身份。
   用 `macos/phase3-tcp/make-signing-identity.sh` 生成一次自签证书，之后重编不再掉授权。

---

## 3. 显示器不跟着切

1. **显示器的 DDC/CI 开关**：ASUS 等品牌在 OSD 里有单独一项，出厂可能是关的。
   关着的话任何软件都切不动。
2. **DDC/CI 只对"当前正在显示的那一路"有效**：屏幕在 DP 上时，Mac 完全看不到这台显示器
   （`system_profiler` 里都没有）—— 所以"切回 Mac"必须由**当时在显示的那一端**发起。
   这就是为什么两端都要能切屏。
3. **输入源编号不对**：`17 = HDMI-1`、`15 = DP-1` 是本机实测值，换显示器就变了。
   写进 `~/Library/Application Support/Traiectus/config.json` 的 `display` 段。
   日志里能看到实际用的值和退出码：`[联动] 屏幕 → Mac/HDMI（m1ddc 62 ms，退出码 0）`。
4. **唤醒瞬间偶发失败**：DDC 在刚唤醒时会以退出码 1、20 ms 返回一次。代码里已重试 3 次；
   如果你看到日志里出现"重试N次"，是正常的。

---

## 4. 键盘换主机了，但屏幕没跟着切

1. **`kvm-keywatch` 有没有起来**：日志里 `[联动] ⚠ 找不到 kvm-keywatch` 就是它没找到
   （正常情况它随 app 打包在 `Contents/Resources/` 里）。
2. **厂商 ID 对不对**：监听的是键盘厂商（默认 Corsair `0x1B1C`）。
   换品牌键盘要改 `config.json` 的 `keyboard.vendorID`。
3. **键盘是不是真的"走了"**：这个工具靠"键盘在 Mac 上出现/消失"判断，
   如果键盘一直挂在别的机器上（比如 USB 接在 Windows 上），Mac 侧当然看不到变化。
4. **抢跑要服务端找到接收器**：服务端启动日志会写"找到接收器 VID_1B1C … usage=0x0002"；
   没找到会写"抢跑不可用，鼠标转发不受影响"并每 30 秒重试。这时只能靠 Mac 侧自己发现
   （"去 Windows"方向慢约 1.7 秒），但仍会切。

---

## 5. 睡眠交接不生效

1. **「键盘联动」开关是不是开的**（设置面板）。关掉联动时，睡眠交接整套都不会做。
2. **自动化授权**：睡眠动作走 `osascript → 系统事件`，需要
   系统设置 → 隐私与安全性 → **自动化** → Traiectus 打勾。没授权时设置里显示「需要授权」。
3. **App 必须活着**：Mac 要**睡眠**而不是关机 —— 关机后 Windows 起来时没人去连它。
4. **看时间线对不对**：

   ```text
   [22:48:34.594] 睡眠快捷键触发 → 请求睡眠
   [22:48:34.696] [联动] 系统即将睡眠 → 把屏幕与鼠标交给 Windows
   [22:48:39]     ← pmset：系统真正睡下去（比交接晚约 4 秒，正常）
   ```

## 6. 其它踩过的坑

| 现象 | 原因 / 处理 |
|---|---|
| 换了仓库目录后编译报 `SwiftShims` 找不到 | 删掉 `macos/phase3-tcp/.build` 和 `build/module-cache` 再编 |
| Dock 里的图标变成问号 | 改过 bundle id。把 Dock 磁贴删掉重新拖一次 |
| 重编 app 后桌面图标还是旧的 | `build.sh` 是**原地更新**（不删整个 .app），图标缓存要等，或 `lsregister -f` 刷一下 |
| 托盘退出后 Windows 光标还锁着 | 有 200 ms 看门狗会自动解锁；如果没解锁，跑一次 `windows/tools/清理旧版本残留.bat` |
| `start-server.bat` 报"没有找到握手口令" | 在同目录建 `token.txt`（一行），或设环境变量 `TRAIECTUS_TOKEN` |
| 托盘弹窗说"token 还是占位符" | `launcher\config.ini` 还没填 —— 从 `config.example.ini` 复制并填入口令 |
| 搜索泄漏时误报一堆文件 | 用**区分大小写**搜索：共享目录名 `SHARED`（大写）会被不区分大小写的搜索算成命中 |
