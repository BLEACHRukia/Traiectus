# Traiectus Server（Phase 3）—— Windows 端捕获并转发

本阶段在 Phase 1（已验证可行的 Raw Input 只读捕获）之上加一个 TCP 服务端：**把 GPW2 的鼠标事件按协议转发给 Mac。**

协议以仓库根目录的 [`PROTOCOL.md`](../../PROTOCOL.md) 为准。方向是 **Mac 主动连过来**，本程序是监听端，默认端口 `45789`。

---

## 1. 安全设计（一条红线都没放松）

| 要求 | 本阶段的实现 |
|---|---|
| 不影响 Windows 鼠标 | 只读捕获，不 hook、不拦截、不 `BlockInput`、不 `SendInput`。**唯一例外：Mac 模式下的 `ClipCursor` 临时锁定**（用户明确要求的 Phase 6 功能，见第 10 节） |
| 不影响键盘 | 只注册鼠标 usage，键盘事件这个进程收不到 |
| 不装驱动 / 不用内核 / 不需要管理员 | 纯 User-Mode，只用 WinSock + Raw Input |
| 不改系统设置 / 注册表 / G HUB / DPI / 固件 | 一个字节都不改（`ClipCursor` 只改"光标可移动范围"这一运行时状态，退出即恢复） |
| **不改防火墙规则** | 一条都不加。首次运行时 Windows 会弹窗询问是否允许，**是否放行由你决定** |
| 退出 / 崩溃后鼠标正常 | Windows 模式下无需恢复任何状态；**Mac 模式下会持有一个 `ClipCursor` 状态，必须恢复**——由独立看门狗 + 系统逃生口双重兜底，见第 10 节 |
| 网络断开后本地鼠标正常 | 发不出去就丢掉，本机鼠标完全不受影响（本程序从不影响本机输入） |

## 3. 运行

```bat
rem 1) 先看有哪些鼠标类设备（选 GPW2 那个）
build\Traiectus-Server.exe --list

rem 2) 正式运行：**什么都不用配** —— 第一次启动会在 8 秒内自动识别
rem    "你真正在用的那只鼠标"（日志里 DEVICE PICK <串>），托盘把它写回 config.ini。
rem    口令同理不用设：第一次有 Mac 连过来时点一次「允许」即可。
build\Traiectus-Server.exe

rem 3) 排查用：把每条转发出去的事件都打印出来
build\Traiectus-Server.exe --verbose
```

停止：在控制台按 **Ctrl+C**。

> `&` 在 cmd.exe 里是命令分隔符，**设备串必须加英文双引号**。

## 4. 防火墙（这一步需要你决定）

首次运行时 Windows 会弹窗："Windows Defender 防火墙已阻止此应用的部分功能"。**勾选「专用网络」并允许**即可。

> 别勾「公用网络」——那会让这个端口在所有网络（包括以后连的咖啡厅 WiFi）上开放。家里/办公内网用「专用」就够。

想更精确的话，可以只针对这个程序加一条入站规则（需要**管理员**权限，属于修改防火墙规则，请你自己执行）：

```bat
rem 添加：只放行这个程序、只放行专用网络、只放行这一个 TCP 端口
netsh advfirewall firewall add rule name="Traiectus Server" dir=in action=allow ^
  program="C:\完整路径\build\Traiectus-Server.exe" protocol=TCP localport=45789 ^
  profile=private enable=yes

rem 不需要时删掉
netsh advfirewall firewall delete rule name="Traiectus Server"
```

如果你的网络被 Windows 标成了「公用网络」，上面这条规则不会生效——把网络配置文件改成「专用」属于系统设置改动，你自己权衡，我不会代改。

## 7. 实现要点

```text
主线程：隐藏窗口 + Raw Input（WM_INPUT）
          └─ 按设备过滤 → 生成协议行 → 塞进发送队列
网络线程：一次 select 同时处理 accept / recv / send / 心跳
          └─ 非阻塞 socket，任何一端慢都不会阻塞主线程
```

| 设计 | 为什么 |
|---|---|
| 每个 WM_INPUT 发一行 `MOVE dx dy` | 不合并、不改写，转发的是设备的原始相对计数 |
| 发送队列上限 8192 行，超了就断开 | 防止对端消费不过来时内存无限增长 |
| 非阻塞 + 部分写处理 | 一次 `send` 可能只发出去半行，剩余部分留到下次可写继续 |
| 心跳 1 秒 / 超时 3 秒 | 及时发现在线状态变化；没有它，TCP 会安静地挂死 |
| 新连接顶掉旧连接 | Mac 重启或重连时不会卡在"旧连接还占着"的状态 |
| `SO_EXCLUSIVEADDRUSE` | 防止同机上其它程序抢占这个端口 |
| 只发相对增量 | 避免两端分辨率/缩放换算不一致导致指针跳变 |

## 8. 已知限制

1. **安全桌面**（UAC 弹窗、Ctrl+Alt+Del、锁屏）下任何用户态程序都收不到 Raw Input，这是系统设计，无解。
2. **应用层看到的是约 145 包/秒**（Phase 1 已实测确认这是 Windows 输入栈的投递粒度，不是丢包）。
3. **绝对坐标设备**（远程桌面、数位板）会被忽略并打印一次提示。
4. **键盘不转发**，由硬件切换。
5. **反作弊**：本程序只读输入并联网发送，不注入、不改内存、不 hook；但玩竞技游戏时建议先关掉它。
6. **代理软件要放行局域网**：服务端发 UDP/收 TCP 用的都是普通 socket，
   "系统代理设置"影响不到它；但如果 Windows 上跑着 **TUN / 虚拟网卡模式**的代理
   （Clash TUN、v2rayN 的 TUN 等），它在 IP 层按路由规则分流 ——
   "私有网段直连"这条规则要是没覆盖到，包就被吞，**而且不报错**：
   Mac 会悄悄收不到 `KEY` 状态帧（抢跑失效、切屏慢 1 秒多）、`HB`、`HERE` 应答。
   判断方法见 `launcher\说明.md` 的常见问题。
   （任何走局域网的 KVM / 屏幕共享 / 串流软件都有这条要求，不是本程序特有。）

## 10. 控制权切换与光标锁定（Phase 5 / 6，已提前实现并实测）

| 项 | 实现 |
|---|---|
| 全局快捷键 | `RegisterHotKey` + 可配置组合键，默认 **`Ctrl+Alt+M`**；`--hotkey <组合键>` 可改（`off` = 不注册）。托盘右键「设置鼠标切换快捷键…」能直接改键并写回 `config.ini`。启动时打一行机器可读状态：`HOTKEY OK/FAIL/OFF <组合键> [错误码]`（托盘读它显示 ✓/✗ 被占用）。语法：修饰键 `+` 连接、最后一段是主键，至少要有 1 个修饰键，主键 A–Z / 0–9 / F1–F24 | 
| Windows 模式（默认） | 不转发任何事件、不加锁定 → Windows 完全原生（打游戏就是这个状态） |
| Mac 模式 | 转发事件 + `ClipCursor` 把 Windows 光标钉在原地（1×1） |
| 模式通知 | 握手完成后、以及每次切换时发送 `MODE <Win\|Mac>`（协议 v1.1，见 [`PROTOCOL.md`](../../PROTOCOL.md) §3.1）|
| 切换顺序 | 进 Mac：**先锁光标，再开始转发**（顺序反了会有极短时间光标乱跑）；回 Windows：**先补发抬起 → 发 `MODE Win` → 停转发 → 解锁** |
| 断线/退出 | 客户端断开、`Ctrl+C`、关窗口、被强杀 —— 一律回到 Windows 模式并解锁 |
| 强杀兜底 | 独立看门狗进程（同一个 exe 的 `--watchdog <pid>` 模式），200 ms 内解锁 |
| 启动参数 | `--start-in-mac-mode` 启动即进 Mac 模式；`start-server.bat mac` 等价写法 |

### 为什么必须有看门狗（实测发现，别删）

**`ClipCursor` 的锁定在进程被强杀后不会自动解除**，Windows 鼠标会卡死在 1×1 的区域里。
这正是红线 13/14（崩溃不能导致鼠标不可用）明令禁止的状态，所以看门狗**不是可选项**。

另外一条同样重要的实测发现：**任何管理员窗口取得焦点时，Windows 会清除别人的 `ClipCursor` 限制**
——打开任务管理器（`Ctrl+Shift+Esc`）光标立刻恢复自由。这是系统级逃生口，**比我们自己的看门狗更可靠**，
不要试图"修"掉它。

### 已知限制

1. 看门狗最长只守 **12 小时**，超时自行退出（之后强杀没有兜底）
2. **点击不会被拦截**：Mac 模式下点击仍会落到 Windows 那个被钉住的 1×1 点上（通常无害）。
   要连点击一起屏蔽就必须用低级鼠标钩子，那属于红线禁止的方案
3. 安全桌面（UAC 弹窗、锁屏）下任何用户态程序都收不到 Raw Input

### 换服务器之前的提醒

看门狗是**同一个 exe** 启动的：如果直接删掉/覆盖正在运行中的 `Traiectus-Server.exe`，
正在守着的看门狗进程仍会继续运行直到它自己判断退出（锁定解除或超时）。正常退出流程不会有这个问题。

## 11. 口令从哪来 + 「重新配对」（协议 v1.2）

### 口令从哪来（服务端**不缓存**，每次握手现读）

```
配对文件  ← 默认 <exe 目录>\..\paired.json（入口会用 --pair-file 显式指过去）
            里面就一行：配对时随机生成的 64 位 hex 口令
没有文件  → 对 HELLO 回 ERR NOPAIR（客户端据此自己发起配对）
```

**`--token` 参数已经删掉了**（2026-10-01，Mac 侧决策）：配对是唯一的鉴权路径。
以前两条路并存会互相打架 —— 设了 `--token` 就再也弹不出配对框。
协议没变，`HELLO` 里照样带口令，只是那个口令永远来自配对文件。

配对流程：Mac 发 `PAIR? <设备名>` → Windows 弹一个自己的确认框 →
点「允许」就生成 64 位 hex 口令、写进配对文件、回 `PAIR-OK <口令>`；
点「拒绝」/关窗回 `PAIR-NO denied`；没人操作则回 `PAIR-NO timeout`
（默认等 **60 秒**，可用 `--pair-timeout <秒>` 调 —— 原来是 30 秒，实测太短：
用户要先在另一台机器上点「连接」，再把显示器输入切过来才点得到按钮）。

> ⚠️ **硬约束：客户端的安全网必须 > 服务端的确认窗口。**
> Mac 侧有一个"等 `PAIR-OK` 等太久就算了"的安全网（当前 **120 秒**）。
> 如果这边把 `--pair-timeout` 调到 120 秒以上，**必须先通知 Mac 侧一起调大**，
> 否则会出现这种死局：用户在 40 秒时点「允许」→ 但 Mac 已经在 120 秒前放弃 →
> `PAIR-OK` 发给一条没人管的连接 → 口令写进了 `paired.json`、Mac 却没收到 →
> 下次 Mac 连过来就是 `already-paired`，只能去托盘「重新配对」。
配对过程中**连接一直保持**：客户端在这段时间不发数据是正常的，服务端不会判死
（这一条是真机联调时发现并修的 bug，见 `给Mac端\回报与排查\` 里的回报）。

### 卡住时怎么办：`PAIR-NO already-paired`

```
Windows 上已经有配对文件（有口令），但 Mac 本地那份口令丢了（重装 / 换机 / 手滑清空）
   → Mac 发 PAIR? → Windows 回 PAIR-NO already-paired（按设计拒绝，防陌生设备顶掉已有配对）
   → Mac 停止重连，用户卡在这里
```

**出路只有一条**：Windows 托盘点「**重新配对**」（删掉配对文件）→
Mac 再点「连接」→ 弹框点「允许」。
Mac 侧已经**没有"手动填口令"的输入框**了，所以只能走这条。

## 12. 地址自动发现（UDP 45791）

全新安装时两边都不知道对方在哪：Mac 是主动连的一侧，得先知道往哪连；
服务端在"还没有任何客户端连过"时，也不知道心跳该发给谁 —— 死锁。
所以由 Mac 先喊一声：

```
Mac     → 广播 "WHO 1"             （第 2 个字段是协议版本）
Windows → 单播回 "HERE 1 45789"     （第 3 个字段是 TCP 监听端口）
```

实现是 `DiscoveryThread()`：一个独立的 UDP socket，
**不依赖任何客户端连接**，服务端一启动就能应答 —— 这正是"全新安装也能自动找到"的关键。
端口用 `--discover-port` 改（默认 45791，0 = 关闭）。

### 三条刻意加的限制（安全相关，别删）

| 限制 | 为什么 |
|---|---|
| **只单播回来源**，绝不回广播 | 回广播等于给反射放大攻击送弹药 |
| **同来源 1 秒内最多回一次**（日志用同一个限速） | 防刷；否则日志和网络都能被一条脚本打满 |
| 回包里**只有版本和端口**，不带口令 / 配对信息 | 这两样端口扫描本来就能拿到，等于没多暴露 |

版本对不上（比如 `WHO 99`）→ **不回包**，只记一条日志，让新旧版本安静地互不打扰；
其它任何报文（含老的 `MODE`）→ 当没看见，**不回过任何错误包**。

### 自测（不需要 Mac）

```powershell
$u = New-Object System.Net.Sockets.UdpClient
$u.Client.ReceiveTimeout = 3000
$b = [Text.Encoding]::ASCII.GetBytes("WHO 1")
$u.Send($b, $b.Length, "127.0.0.1", 45791) > $null
$ep = New-Object System.Net.IPEndPoint([Net.IPAddress]::Any, 0)
[Text.Encoding]::ASCII.GetString($u.Receive([ref]$ep))     # 期望：HERE 1 45789
```
