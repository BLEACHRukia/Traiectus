# Traiectus 统一入口（托盘）—— 说明

目录：`%USERPROFILE%\Desktop\SHARED\launcher\`

---

## 一、这是什么

把 Windows 端从「服务端 + 桥接各自为政」改成一个手动入口。

- 打开 → 服务端起来（桥接已退役，默认不再拉起，见下）
- 点「退出」→ 服务端、看门狗、端口、光标锁定**一次性全清掉**
- 托盘显示状态：**灰点** = 已停止，**绿点** = 运行中，**红点** = 异常

刻意**不做「停止」这个中间态**——运行中只能「重启」或「退出」，避免状态含糊。

**不加开机自启**，也不注册 Windows 服务。想用就手动打开，不用就退出，
打游戏前能有一个完全干净的环境。

---

| 文件 | 作用 |
|---|---|
| `Traiectus.cpp` | 入口程序源码 |

## 三、怎么用

### 方式一（推荐）：直接在项目目录里运行，不装任何东西

1. 双击 `build-launcher.bat` → 产出 `launcher\Traiectus.exe`
2. 右键 `建桌面快捷方式.ps1` → 使用 PowerShell 运行 → 桌面出现 `Traiectus`
3. 双击桌面的 `Traiectus`

入口会自己去找 `..\phase3-tcp\build\Traiectus-Server.exe`，
**不需要安装任何东西**。（`TraiectusBridge.ps1` 只在 `[bridge] cmd=` 填了东西时才会拉起，默认留空。）日志写在 `launcher\Traiectus-Server.log`（见第七节）。

这个方式最稳：exe 就在项目目录里，路径永远不会因为重定向而失效。

### Mac 那边怎么找到这台电脑

**不用填 IP，填了个"自动发现"更省事：** 服务端在 UDP 45791 上等一句广播 ——
Mac 喊 `WHO 1`，它就单播回一句 `HERE 1 45789`（告诉对方 TCP 端口）。
所以 Mac 装好后直接点「连接」就行，它会先试记住的地址，再广播问一声。
（这个应答不依赖任何客户端连接，全新安装也能用。）

### 方式二：装到 %LOCALAPPDATA%\Traiectus

双击 `安装 Traiectus.bat` → 装到 `%LOCALAPPDATA%\Traiectus\`，并建桌面快捷方式。

⚠️ **这一步必须由你自己双击运行，不要让 Codex / AI 代跑。** 原因见第八节最后一条。

安装脚本会顺手移除旧的后台桥接自启（启动文件夹里的 `TraiectusBridge.lnk`），
否则会出现两个桥接同时跑。

### 平时

- 桌面双击 `Traiectus` → 托盘出现灰点，几秒内转绿，说明服务端起来了
- 不用了 → 右键托盘圆点 → **退出**

### 不想用了

- 方式一：删掉桌面快捷方式，`launcher\` 里删掉自动生成的 `.log` 就行
- 方式二：双击 `卸载 Traiectus.bat`

两种方式都不会碰注册表、服务、驱动、防火墙。

## 四、右键菜单

```
状态：运行中                        ← 下面几行都是灰色不可点的状态显示
本机：192.168.1.20
鼠标切换：Ctrl+Alt+M ✓
鼠标：VID_xxxx&PID_xxxx&MI_00 ✓
------------------------
设置鼠标切换快捷键…      ← 见下面「改键」
检测鼠标…                ← 重新识别一次（见下面「鼠标设备」）
------------------------
重启                    ← 只在运行中时出现
重新配对                ← 见下面说明
打开日志目录
------------------------
语言  →  中文 / English   ← 点一下当场生效，写回 config.ini
------------------------
退出
```

停止状态时「重启」那行会变成「启动 Traiectus」。

「**本机**」是当前默认路由那块网卡的 IPv4 地址（不会显示 Tailscale/虚拟网卡的地址），
每次打开菜单都重新查一次 —— 有这一行就够判断 Mac 该连哪个地址。启动时服务端还会打一行更全的：
`本机网络：WLAN 192.168.1.20 网关 192.168.1.1 DHCP租约 过期 …`。

### 关于「语言」

点 **中文** 或 **English**，菜单和悬停提示**当场就变**，不重启进程。选择会写回
`config.ini`（`[ui] language=`），重启入口、甚至重启 Windows 之后仍然有效。

用哪种语言的优先级：

1. 命令行 `--lang zh|en`（只管这一次运行，不写回配置）
2. `config.ini` 里的 `[ui] language=`
3. 都没有时看 Windows 的界面语言 —— 中文 Windows 用中文，其它用英文

这个选择会一起传给服务端（`--lang`），所以配对弹框、`--show` 窗口、`--help`、`--list`
都跟着同一个语言。**日志两种语言下都保持中文** —— 托盘要从服务端日志里 grep
`:45789`、`DEVICE …`、`HOTKEY …` 这些机器可读的行。

### 关于「设置鼠标切换快捷键…」（改键）

### 关于鼠标设备（「检测鼠标…」）

**正常情况下你什么都不用配。** 只要 `config.ini` 的 `args` 里**没有 `--device`**
（模板里默认就是没有），服务端启动后会自己观察 **8 秒**：

    "这段时间里哪个设备真的产生了鼠标事件，那只就是你要用的鼠标。"

它不靠枚举设备列表 —— 列表里全是虚拟设备、接收器的第二个接口、触控板，用户根本选不对；
**"谁真的在动"才准**。观察结束会打一行 `DEVICE PICK <设备串>`，托盘把它写回
`config.ini` 并重启一次，之后只转发这一只鼠标。

托盘右键菜单第二行会显示当前状态：

| 显示 | 意思 |
|---|---|
| `鼠标：VID_xxxx&PID_xxxx&MI_00 ✓` | 正常，就是这只 |
| `鼠标：全部（未指定）` | 没配设备串 = 所有鼠标类设备都转发 |
| `鼠标：✗ 未匹配（换鼠标了？点「检测鼠标…」）` | 配的串一个事件都没匹配上（换鼠标/换接口了） |
| `鼠标：检测到 N 个 → 点「检测鼠标…」选一个` | 有多个设备都动过，需要你点名 |
| `鼠标：没检测到 → 点「检测鼠标…」重试` | 那 8 秒里没人动鼠标 |

**换鼠标了怎么办**：点「**检测鼠标…**」→ 服务端用 8 秒重新识别：

- 只有一个设备动过 → 直接锁定，写回配置
- **多个设备动过（比如笔记本的触控板也动了）→ 弹一个小窗列出候选，你点一个**，不自动猜
- 一个都没动 → 提示重试

另外：如果配的串**一直在丢事件**（换了鼠标但没改配置），服务端 10 秒后会打一行
`DEVICE MISS <串>` 并**自动重新识别一次** —— 也就是说换了鼠标不用改配置，
晃一下鼠标它自己就能恢复。

> ⚠️ 手工改过 `config.ini` 之后，要**重启托盘**才生效（托盘启动时读一次配置）。
> 用菜单里的「检测鼠标…」/「设置鼠标切换快捷键…」改则不用，它会自己重启服务端。

点开是一个小窗：**按一下你想要的组合键**，中间会把捕获到的组合显示出来，点「保存」
就写回 `config.ini` 的 `--hotkey` 并自动重启服务端（几秒，Mac 会闪断一下再自动连回）。

规则：

| 操作 | 行为 |
|---|---|
| 按组合键 | 立刻显示，窗口里固定写着支持范围：修饰键 Ctrl / Alt / Shift / Win（至少一个），主键 A–Z / 0–9 / F1–F24 |
| 只按主键、没按修饰键 | 提示"至少要有 1 个修饰键"，**「保存」变灰**（裸键注册成全局热键会毁掉正常打字） |
| `Esc` | 关窗，什么都不改 |
| `Delete` / `Backspace` | 清空 = 保存成 `off`（不使用热键），菜单上显示"鼠标切换：未设置" |
| 保存 | 就地改 `config.ini` 那一行，**其它行一个字节都不动**，然后重启服务端 |

菜单第一行会显示**实际注册成功没有**（读的是服务端日志里的状态）：

```
状态：运行中   鼠标切换：Ctrl+Shift+M ✓            ← 注册成功
状态：运行中   鼠标切换：Ctrl+Shift+M ✗ 被占用      ← 被别的程序抢先占了（日志里有 HOTKEY FAIL … 1409）
状态：运行中   鼠标切换：未设置                     ← 保存成了 off
```

⚠️ **注册成功 = 这个组合键在全系统被本程序独占**，别的程序（包括游戏）拿不到它。
所以别选你常用软件里的快捷键。

### 关于「重新配对」

它的作用是**删掉配对文件**（默认 `phase3-tcp\paired.json`，如果你在
`config.ini` 的 args 里写了 `--pair-file`，就是那个路径）。
服务端不缓存口令、握手时现读文件，所以删掉之后 **Mac 下一次连接就会被重新询问一次**。
对已经连着的会话没有影响。点了会先弹一个确认框，问清楚要删哪个文件。

口令只有配对文件这一个来源（2026-10-01 起 `--token` 参数已经删掉），
所以**这一项永远是可点的**，动作也只有"删掉那个文件"这一个。

## 五、点「退出」会清掉什么

| 会清掉 | 怎么清的 |
|---|---|
| 服务端 `Traiectus-Server.exe` | Job Object |
| 桥接 `powershell + TraiectusBridge.ps1`（**已退役，默认不启动**） | Job Object |
| 服务端自己起的看门狗进程 | Job Object（一起被带走） |
| 端口 45789 / 45790 / 45791 | 进程没了，端口自然释放（45789 TCP 鼠标事件、45790 UDP 抢跑、45791 UDP 地址发现） |
| 光标锁定 | 入口自己调 `ClipCursor(NULL)` 兜底 |
| 托盘图标 | 主动移除 |

**Job Object 是核心**：入口进程创建一个 Job，用
`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` 把子进程都放进去。
入口一消失（正常退出、被强杀、崩溃），内核会把 Job 里所有进程**连同子孙进程**
一起杀掉。这比 `taskkill` 逐个杀可靠得多，不会漏掉看门狗。

## 六、实现说明（刻意的设计选择）

这一节记的是**看起来奇怪、但都是故意这么做**的地方，以及当初实现时踩到的坑。
改代码之前先看这一节。

### 6.1 被拼坏的残片（编译不过）

`#define TIMER_HEALTH 1` 后面原来跟着这样两行：

    }
    if (g_hBridge// ---------- 全局 ----------

这是文件被错误拼接留下的碎片，**编译不过**。已删除。

### 6.2 `StopServices()` 里括号错位

原来的写法（**编译不过**）：

    if (g_hServer) { ... g_hServer = NULL;) { WaitForSingleObject(g_hBridge, 1000); ... }

已改成两条独立语句，并给 Job 关闭后留了 300 ms 让内核把子进程收干净。

### 6.3 `#include` 顺序错误

`<windows.h>` **不能**写在 `<winsock2.h>` 前面：
这会让 windows.h 先引入老的 winsock.h，再引 winsock2.h，**满屏重定义错误**。
已改成 winsock2.h 在前，并加上 `WIN32_LEAN_AND_MEAN`。

### 6.4 用「连一下 45789」判断服务端就绪 —— 会把 Mac 挤下线

原来判断服务端起没起来，用的是 `WaitPortReady()` —— 往 `127.0.0.1:45789` 建一条 TCP 连接。
但服务端**同一时刻只服务一个客户端，而且新连接会无条件顶掉旧连接**
（`phase3-tcp\src\main.cpp` 第 810 行，注释里也写着"新连接顶掉旧的"）。

所以这个探测连接有可能把已经连上的 Mac 踢掉。

已改成**只读服务端自己的日志**：服务端 `listen()` 成功后会打印
`监听 0.0.0.0:45789（TCP）`，我们只在日志文件里找 ASCII 子串 `:45789`，
完全不去碰端口。

### 6.5 编译命令缺 `-static` —— 装完打不开

编译命令漏掉 `-static` 时，产出的 exe 会依赖
`libstdc++-6.dll` / `libgcc_s_seh-1.dll`。
一旦被 `安装 Traiectus.bat` 复制到 `%LOCALAPPDATA%\Traiectus\`，
从桌面双击就会弹「找不到 DLL」。

已加上 `-static -static-libgcc -static-libstdc++`，并用 `objdump` 验证过：
现在只依赖 6 个系统 DLL（KERNEL32 / USER32 / GDI32 / SHELL32 / WS2_32 / msvcrt）。

### 6.6 路径假设和实际目录不符

分发到 Windows 那台机器之后，目录结构不一定跟仓库里一样
（比如项目文件夹直接从 `SHARED\` 开始）。

处理方式：程序自己找文件——先在 exe 同目录找，找不到再试
`..\phase3-tcp\build\` 和 `..\`。这样**同一份 config.ini**
在开发目录和安装目录下都能直接用。

### 6.7 单实例锁用会话内名字

没有用 `Global\`：`Global\` 命名空间对普通用户进程可能创建失败，而托盘程序本来就是
每个登录会话一个。已加 NULL 检查。

### 6.8 桥接的日志拆成两个文件

桥接自己的 `-OutFile TraiectusBridge.log`，入口重定向的输出写
`TraiectusBridge-console.log`。不拆的话两个写入者会抢同一个文件。

### 6.9 健康检查：要么全开，要么全关

原来的健康检查是「服务端死了 → 托盘转红」，然后就没动作了。实测发现这会导致：

1. 桥接变成**没人管的野进程**，继续往 Mac 发 UDP；
2. 此时再点「启动 Traiectus」，会**又拉起一个桥接** —— 两个桥接同时发 UDP；
3. 旧的 Job 句柄被覆盖，泄漏。

已改成：**任一子进程退出，就把另一部分也一起收干净**，不留"半死不活"的中间态；
`StartServices()` 在拉起之前也会先清掉上一轮的残留。

这一条和「不做停止中间态」是同一个思路：要么全开，要么全关。

### 6.10 关于 `.bat` 为什么是英文

这个目录里所有 `.bat` 的内容都是**纯 ASCII**（你原来那批脚本也是）。
原因：cmd.exe 按本地 OEM 代码页读 `.bat` 的字节，内容里出现中文会被解码成乱码，
整段脚本报一串 `'xxx' is not recognized`。
安装脚本里写 `chcp 65001` + 中文 `echo` 是不可靠的，所以改成全英文。
中文说明都在这份 `.md` 里。

## 七、日志

都在**入口程序所在的目录**（你这台是 `SHARED\launcher\`；
装到 `%LOCALAPPDATA%\Traiectus\` 的话就是那个目录 —— 反正跟着入口程序走）：

| 文件 | 内容 |
|---|---|
| `Traiectus-Server.log` | **当前唯一的活跃日志**：服务端全部输出。每次启动会截断重开，只看这一次运行 |
| `TraiectusBridge-console.log` | 历史文件（键盘状态帧并进服务端、桥接退役之后就不再更新了） |
| `TraiectusBridge.log` | 同上，历史文件；只有把桥接临时开回来做对照时才会重新写 |

文件名由 `config.ini` 的 `[server] log=` / `[bridge] log=` 决定，默认就是上面这两个。

右键托盘的「打开日志目录」会直接打开这个文件夹。

启动超时的情况下，程序会弹窗告诉你去哪里看日志。

## 八、常见问题

### 托盘一直是灰点，不变绿

服务端没起来。看 `server.log`；双击桌面的 `Traiectus` 时会弹窗提示原因。
最常见的是 `phase3-tcp\build\Traiectus-Server.exe` 不存在（先跑
`phase3-tcp\build-mingw.bat`）。

### 托盘变红

某个子进程退出了，鼠标悬停在圆点上会显示是"服务端已退出"还是"桥接已退出"。
右键 → 启动 Traiectus 就能重新拉起来。

### 双击 Traiectus 没反应

可能已经在运行了。再双击一次只会把菜单弹出来，不会开第二个进程（这是设计）。

### 指针看不见（能点能移，就是看不到）

**先分清是谁的问题** —— 本项目的锁定只会让光标**停住不动**，永远不会让它**消失**：

```powershell
# 1) 系统的光标裁剪区：全屏 = 没锁；1x1 = 锁着（Mac 模式）
# 2) 光标方案指向的那些文件到底在不在
Get-ItemProperty "HKCU:\Control Panel\Cursors" | Select-Object '(default)', Arrow
```

- **裁剪区是全屏、而且托盘第一行不是 Mac 模式** → **不是本项目的问题**。
  2026-10-07 在真机上见过一次：桌面主题（`Custom.theme`）把 15 个光标全指向
  `C:\WINDOWS\Resources\Themes\Golden Gate\Cursors\`，而**那个目录不存在** ——
  指针没有图可画，于是能点能移、就是看不见。修法：设置 → 蓝牙和其他设备 → 鼠标 →
  其他鼠标设置 → **指针** → 挑一个方案 → 应用；同时把那个 `.theme` 文件里的路径也改掉
  （否则再套用那个主题还会坏）。
- **托盘第一行显示 Mac 模式、光标不动** → 是本项目的锁定，按 `Ctrl+Alt+M` 切回去。

### 改了口令或设备，要改哪里

`config.ini` 里的 `server.args`。改完要重新双击 `安装 Traiectus.bat`
把新配置复制到安装目录，或者直接改 `%LOCALAPPDATA%\Traiectus\config.ini`。

**口令不用填** —— 配置里没有这种参数了（`--token` 已经删掉）。
口令由 Windows 在配对时随机生成、存在 `phase3-tcp\paired.json` 里，
Mac 自己记下来。两台机器都不用打字。要改的是 `--device`（鼠标设备串）和端口。

### Mac 第一次连过来时，Windows 上弹的那个框是什么

那是**配对确认框**（只在"这台 Mac 还没配过对"的时候出现，之后不再打扰你）。
照 macOS 权限弹窗的样子做的 —— **没有标题栏**的圆角浮层，两行内容：

```

        有一台 Mac 想连接这台电脑

            [ 允许 ]  [ 拒绝 ]
```

- 点「**允许**」→ 生成口令、Mac 记住，以后自动连
- 点「拒绝」/ 按回车 / 按 Esc → 都算拒绝（默认按钮也是拒绝）
- **60 秒不操作 = 自动拒绝**（`--pair-timeout <秒>` 可调；原来 30 秒太短，
  实测"要在另一台机器上点连接、再把显示器输入切过来"根本来不及）
- 想反悔：托盘右键 →「重新配对」，删掉配对文件，Mac 下次连过来会重新问一次

排版是按视觉设计原理算的（不是写死的像素）：文案 13pt、按钮 12pt（108×34），
窗口尺寸由内容决定（`max(文案宽, 按钮行宽) + 左右留白 28`，夹在 380~480 之间），
文字行的盒子高度取字体的实际行高，顶部留白（28）比下边缘（26）略大 ——
因为这一行中文没有下伸部，视觉重心天生偏高，等值留白会看起来"贴顶"。

### Windows 已经配对过了，Mac 那边却说连不上（`already-paired`）

这个提示的意思是：**Windows 上有配对文件（已经有口令），但 Mac 本地没有那份口令**
（重装、换机，或者你在 Mac 界面上把口令清空了）。Mac 这时会发配对请求，
而 Windows 按设计拒绝重新配对（防止陌生设备把已有配对顶掉），所以 Mac 停在
「这台 Windows 已经配对过了」。

**Mac 端自己解决不了**，需要在这台 Windows 上二选一：

**唯一的出路**：托盘右键 →「重新配对」→ 确认 → 回 Mac 点「连接」→
弹出确认框点「允许」。Mac 那边已经**没有"手动填口令"的地方了**（输入框已删），
所以只能走这条。

### 双击桌面 Traiectus 没反应 / 提示找不到文件

### 换了 IP、或者「抢跑」突然不灵了？

（先说"抢跑"是什么：你在键盘上切到 Mac 时，Mac 会**提前**把屏幕切过去，
省掉那 1 秒多的等待。它靠的是服务端把键盘接收器的状态帧发给 Mac。）

**如果这台 Windows 上跑着代理软件**（Clash / v2rayN / Surge / 各种 TUN 模式），
代理有可能把**发往局域网的包吞掉** —— 而且不会报任何错：

| 代理模式 | 对 Traiectus 的影响 |
|---|---|
| 只填了系统代理（HTTP / SOCKS） | **不影响** —— 服务端发 UDP 用的是普通 socket，WinSock 不认系统代理设置 |
| TUN / 虚拟网卡模式 | **有风险** —— 它在 IP 层抓包、按规则分流；规则里"局域网直连"没覆盖到，包就没了 |

被吞掉时，Mac 那边会**悄悄失去三样东西**：

- `HB` 心跳、`HERE` 应答 → Mac 学不到地址（退化成广播/扫描，慢一点但还能连上）
- **`KEY` 状态帧 → 抢跑失效、切屏慢 1 秒多**（最容易被察觉，也最难查）

**怎么判断**：看 **Mac 客户端**的日志里有没有 `⚡ Windows 抢跑：键盘正在…` 这几行。
**没有 = 状态帧没到 Mac = 抢跑没生效**。

**怎么修**：在代理软件里把**私有网段设成直连 / 绕过**：
`192.168.x.x`、`10.x.x.x`、`172.16~31.x.x`，以及广播地址 `224.0.0.0/4`。
一般是默认就有的，**自己改过分流规则的**才需要检查。

> 这不是 Traiectus 特有的要求 —— 任何走局域网的 KVM / 屏幕共享 / 串流软件
> 都需要"局域网直连"。代理只应该代理**出网**的流量。

### 日志里出现「客户端接入…」3 秒后又「超过 3 秒没收到对端任何数据」

**多半不是故障，是 Mac 在自动找地址。**

Mac 那边"自动查找 Windows"的最后一层是**扫自己网段**（254 个地址），
它会挨个敲 45789 这个 TCP 端口。而服务端同一时刻只接受一个客户端，
所以这些探测包会短暂地把连接挤一下 —— 表现就是上面那两行。

正常使用时不用管（Mac 扫完就连上真正的那台了）。要注意的只有一种情况：
**如果同时有第二台 Mac 连着这台 Windows**，别人那边跑一次扫描会把它顶掉
（它会自动重连）。单人使用遇不到。

说明快捷方式指向的 exe 不在了。

**你**在 `launcher` 目录里右键 `建桌面快捷方式.ps1` → 使用 PowerShell 运行，
它会把快捷方式重新指向本目录的 `Traiectus.exe`。

### ⚠️ 为什么安装脚本必须你自己双击，不能让 Codex / AI 代跑

`安装 Traiectus.bat` 会往 `%LOCALAPPDATA%\Traiectus\` 写文件。

如果这个脚本是被 **Codex 代跑**的，那么它运行在 Codex 应用自己的容器里，
写 `%LOCALAPPDATA%` 的内容会被重定向到

    %USERPROFILE%\AppData\Local\Packages\OpenAI.Codex_<...>\LocalCache\Local\Traiectus\

结果就是：**文件确实装好了（在容器副本里），但桌面快捷方式从你的角度看
指向一个不存在的位置，双击没反应。**

所以：

- 涉及 `%LOCALAPPDATA%` 的安装 / 卸载 → **你自己双击**
- 涉及项目目录（`SHARED\...`）的操作 → 没有这个问题，谁跑都一样

这也是为什么上面"方式一"被列为推荐做法：它完全不用 `%LOCALAPPDATA%`。

## 九、进程与资源占用（含一次走了弯路的优化）

正常运行（Windows 模式）只有 **2 个进程**：

    名称                    内存      说明
    Traiectus.exe             ~10 MB    入口（托盘）
    └─ Traiectus-Server.exe    ~7 MB    服务端

按 Ctrl+Alt+M 进 Mac 模式会**多一个**（切回来就消失，不会累积）：

    Traiectus-Server.exe --watchdog <主进程PID>   ~7 MB   兜底：主进程被杀后 200 ms 内解除光标锁定

### 关于 conhost

Windows 会给每个「控制台子系统」的程序配一个 `conhost.exe` 宿主进程 ——
**即使窗口不可见也照样配**。服务端只往重定向文件里 printf、不需要控制台，所以创建它时用
**`DETACHED_PROCESS`** 而不是 `CREATE_NO_WINDOW`，省掉一个 conhost。

> **踩过的坑**：老的桥接是 `powershell.exe`，它**必须有控制台**。也用 `DETACHED_PROCESS`
> 起它 → 一行输出都没有、`TraiectusBridge-console.log` 是 0 字节、进程立刻消失；1 秒后
> 健康检查判定「桥接已退出」，按第五节「不留半截状态」的规则**把服务端也一起收干净了**。
> 表面看像「服务端自己崩了」，其实 Windows 事件日志里**没有崩溃记录，是正常退出** ——
> 正是被 Job 收走的特征。
>
> 所以现在的规则是：服务端 → `DETACHED_PROCESS`；任何需要控制台的 → `CREATE_NO_WINDOW`。

### 关于「清理干净」

托盘右键 →「退出」会把服务端、看门狗、端口、光标锁定一次性清掉（见第五节）。
**没有 Windows 服务、没有开机自启项、后台不留东西。** 打游戏前退掉，系统里就没有它的痕迹。

## 十、安全声明

这个入口本身**不碰**任何输入设备：

- 不 hook、不拦截、不注入、不装驱动
- 不注册服务、不加开机自启、不改注册表
- 不改防火墙（需要的规则仍由 `windows/control-channel/Traiectus-防火墙放行.bat` 负责 ——
  需要入站放行的是 **TCP 45789** 和 **UDP 45791**（地址发现）；UDP 45790 是服务端发出去的，
  回包走临时端口，不用单独放行）

它只做三件事：启动两个进程、显示托盘状态、退出时把它们清干净。
