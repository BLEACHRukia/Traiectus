# K70 键盘切换 · 第三轮：单次发送测试（Windows → 键盘）

**来自**：Mac 侧（Deep）　**日期**：2026-09-25

---

## 0. 上一轮结果（已收到，结论如下）

`K70-Probe-Result.txt` 一次性回答了三件事：

| 问题 | 答案 |
|---|---|
| `1BA6` 是什么 | **`CORSAIR SLIPSTREAM WIRELESS USB Receiver`**，序列号 `A5EF…（序列号已隐去）` → 就是 SLIPSTREAM 接收器，不是键盘本体 |
| 厂商接口期望多少字节 | **65 字节**（64 字节报告 + 1 字节 Report ID），写目标是 `usagePage 0xFF42 / usage 0x01`（`MI_01`） |
| 与键盘直连（1025 字节）是否同一套 | **不是**。接收器这套 = OpenLinkHub 的 `k70pmW` 路径（buffer 64 / 写 65），键盘直连 = `k70pmWU`（1024 / 写 1025） |

（Report Descriptor 读不出来是正常的：该接收器接口不响应那个 IOCTL；报文长度已由 `HidP_GetCaps` 给出，够用了。）

---

## 1. 这一轮要验证的唯一问题

> 键盘此刻正以**蓝牙**连在 Mac 上（2.4G 链路是断的）。
> **接收器能不能把"切换命令"送到这样的键盘上？**

能 → 你要的"不动线、不按 Fn 的纯软件双向切换"成立。
不能 → 回程只能靠 `Fn` 组合键，Mac 侧会把结论写进文档，不再折腾。

---

## 2. 要发的报文（65 字节）

```text
00 08 01 3A 00 01   + 59 个 00   → 键盘切到 SLIPSTREAM（Windows 抢键盘）
00 08 01 3A 00 02   + 59 个 00   → 键盘切到蓝牙 Host 1（还给 Mac）
```

逐字节：`00` = Report ID、`08` = 端点/通道、`01 3A` = Connection Mode 命令、`00` = 固定参数、末字节 = 模式。

> `08` 这个端点值是沿用键盘直连时实测过的通道值（Mac 侧发过的就是 `00 08 01 3A 00 02`）。
> 接收器路径是否也是 `08`，是本次测试里的未知量之一 —— 所以**先 A 步、后 B 步**。

---

## 3. A 步：dry run（现在就可以做，绝对不发送）

**最省事：双击 `K70-A-只检查不发送.bat`**（Windows 上现在没有键盘可用，这三个 bat 都是为了"只用鼠标"做的）：

```text
K70-A-只检查不发送.bat     ← 现在双击这个（只读，不发任何数据）
K70-B-切到Windows.bat      ← 等 Mac 侧放好 K70-GO.txt 再双击（真发一次 → SLIPSTREAM）
K70-C-切回Mac.bat          ← 同理（真发一次 → 蓝牙 Host 1，等于把键盘还给 Mac）
```

每个 bat 的结果都会写进同目录的 txt（`K70-Send-A-Result.txt` / `-B-` / `-C-`），
窗口不会等你按键，60～90 秒后自己关闭（也可以点右上角 X）。

如果你想手动来，在 Windows 的共享文件夹里把下面整行粘进 **PowerShell**（普通权限即可，不用管理员）：

```powershell
cd \\192.168.1.20\SHARED    # 如果已经在共享文件夹里，跳过这行
powershell -NoProfile -ExecutionPolicy Bypass -File .\K70-Send.ps1 -Hex "00 08 01 3A 00 01" -Length 65
```

它会打印：目标接口路径、产品名、`usagePage`、`output-report-bytes`、将要发送的完整报文预览，
以及一行 **`open for write : OK / FAILED`**（FAILED 通常表示 iCUE 正在独占那个接口）。

**把这段输出整份回传**（或截图），Mac 侧确认后再进行 B 步。

## 4. B 步：真发一次（**等 Mac 侧说"可以"再跑**）

**双击 `K70-B-切到Windows.bat`** 即可 —— 但它有一个硬门槛：**同目录里必须存在 `K70-GO.txt` 才会真的发送**。
那个文件由 Mac 侧在"准备好看结果"的时候放进去；发完会自动删掉，所以不会重复发第二次。
没有 `K70-GO.txt` 时它只会打印 `NOT SENT`，不碰键盘。

等价的手动命令（同样需要 `K70-GO.txt` 才安全，建议直接用 bat）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\K70-Send.ps1 -Hex "00 08 01 3A 00 01" -Length 65 -Execute
```

注意点：

- **只发一次**，脚本本身也只调用一次 `HidD_SetOutputReport`，没有循环、没有重试、没有后台
- Mac 侧会同步开着 `tools/k70-watch.py` 监视，键盘一旦离开 Mac 会带时间戳记录下来
- 发完观察两件事：
  1. **Windows 上键盘能不能打字**（打开记事本敲几个字）
  2. Mac 侧是否记录到键盘消失

如果键盘真的跳到 Windows 了，Mac 侧会给出发回命令（同一条命令把末字节改成 `02`），
同样只发一次 —— 这一次是验证"能不能送回去"，成功即打通双向。

---

## 5. 回退手段（万一键盘跑掉）

按优先级：

1. 键盘上 `Fn + T` = 蓝牙 Host 1（回 Mac）
2. 键盘上 `Fn + Caps` = SLIPSTREAM（回 Windows）
3. 把键盘的 USB 线插到任一机器上（插上即回到有线模式）

鼠标不受影响：Traiectus 的鼠标转发与这条键盘通道完全无关。

---

## 6. 安全边界

- A 步完全只读：只打开接口再立刻关闭，**一个字节都不发**
- B 步只发一次 65 字节的厂商 output report，不改键盘配置、不改固件、不装驱动、不动注册表
- 不拔插接收器、不拔插键盘线、不改任何系统设置
- 若 `open for write` 是 FAILED：先别发，回报 Mac 侧（大概率是 iCUE 占用）

## 7. 如果 B 步失败（已经发生，2026-09-25 21:43）

第一次 B 步的结果是：

```text
HidD_SetOutputReport : False
GetLastWin32Error    : 0 (no error)
```

键盘没有离开 Mac。这说明 **`HidD_SetOutputReport` 这个入口在该接收器接口上被拒绝**，
而不是"命令到达了键盘但键盘不理"（那样返回值应当是 `True`）。

于是有了 **B2**：完全相同的 65 字节报文，换成 **`WriteFile()`** 发 —— 这正是 hidapi 在 Windows
上真正使用的入口（`HidD_SetOutputReport` 是另一个入口，两者对驱动的要求不同）。
B2 还会补上真实的 Win32 错误码（上一次那行 `error 0` 是 P/Invoke 声明漏了 `SetLastError` 导致的假值）。

**双击 `K70-B2-切到Windows.bat`** 即可（同样需要 `K70-GO.txt`，同样只发一次）。
结果写在 `K70-Send-B2-Result.txt`。
